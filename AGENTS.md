# AGENTS.md

Notes for AI coding agents (and humans) working in this repo.

## What this is

**Minigames**: a collection of party games, either for one shared screen (pass the
phone or laptop around) or one phone per player, connected peer to peer. It is a **static site** in `site/`, deployed to **GitHub Pages**
by `.github/workflows/pages.yml` on every push to `main`. There is no backend.

Python + [uv](https://docs.astral.sh/uv/) is only tooling:

```sh
uv run minigames            # build games.json, serve site/ at http://127.0.0.1:8765/
uv run minigames build      # only regenerate site/games.json
uv run minigames --host 0.0.0.0   # test on a phone on the same network
```

## Layout

```
site/                      everything that gets deployed
  index.html               hub: reads games.json, shows one card per game
  games.json               GENERATED by `minigames build` (committed so the site works as-is)
  shared/brand.css         THE place to rebrand: color tokens (light + dark), fonts, radii
  shared/theme.css         shared base built from brand.css: type, buttons, panels, face, chip
  shared/pwa.js            registers the service worker (include in every page with data-root)
  shared/mesh.js           serverless multiplayer rooms over WebRTC (see "Multiplayer" below)
  shared/qr.js             QR code generator (SVG), no dependencies
  shared/qr-scan.js        QR code reader for camera frames (our codes: byte mode, level L/M)
  manifest.webmanifest     PWA manifest; the hub is the installable app (start_url ./)
  sw.js                    service worker: network-first with offline cache, precaches games.json games
  icons/                   PWA icons, drawn by `uv run minigames icons`
  games/<slug>/
    game.json              { title, tagline, players, order } shown on the hub
    index.html             the whole game: markup, game CSS, game JS
    *.js                   optional modules next to it (listed in games.json "files" for offline)
                           multiplayer games keep their page script in game.js (see Security)
src/minigames/cli.py       `build`, `serve` and `icons` commands (standard library only)
src/minigames/icons.py     stopwatch icon drawn with the standard library
tests/test_site.py         page rules (head, relative paths, no raw colors), sw.js, games.json
tests/js/*.test.mjs        node --test: QR codec and reader, mesh room logic, game rules
.github/workflows/pages.yml  uv run minigames test -> build -> upload site/ -> deploy Pages
```

## Rules

- **Static only.** No server APIs, no build step beyond `games.json`. Anything a
  game needs to remember goes in the browser's `localStorage` (wrap in try/catch).
- **Relative paths only.** Pages serves the site under `/<repo-name>/`, so never use
  leading `/` in hrefs, srcs or fetches. A game links the theme as
  `../../shared/theme.css` and back to the hub with `<a class="back" href="../../">`.
- **Shared style.** Pages link only `shared/theme.css`; it imports `shared/brand.css`,
  which holds every brand value. Use its tokens and never hard-code colors, fonts
  or radii in a game:
  - colors: `--bg`, `--panel`, `--fg`, `--muted`, `--line`, `--accent`, `--accent-fg`,
    `--good`, `--pop-1`, `--pop-2`, `--face`, `--face-fg` (each is `light-dark(light, dark)`)
  - type: `--display`, `--body`, `--mono`, `--display-weight`, `--display-case`
  - shape: `--radius-sm`, `--radius`, `--radius-lg`
  Reuse the shared classes (`.panel`, `.face`, `.chip`, `.primary`, `.label`, `.hint`,
  `.mono`, `.row`, `.field`, `.back`) before writing your own. Derive tints with
  `color-mix(in srgb, var(--accent) 25%, transparent)`. Canvas/JS can't read
  `light-dark()` tokens directly: resolve them through an element's computed
  `color` (see the confetti in Second Shot).
- **Rebranding** = edit `shared/brand.css`, plus the colors in `manifest.webmanifest`
  and the icons (`src/minigames/icons.py`). The browser bar color follows `--face`
  via `shared/pwa.js`.
- **Mobile first-class.** Touch targets at least 44px, `pointerdown` for timing-
  critical input, no hover-only features, layout must work at 360px wide, respect
  safe-area insets and `prefers-reduced-motion`.
- **Keyboard too.** Space/Enter should drive the main game action where it makes sense.
- No dependencies in `pyproject.toml` unless really needed; the site loads no JS libraries.

## PWA

The hub (`site/index.html`) is installable. `sw.js` is network-first, so online
users always get the latest files; offline it serves the cache. It precaches the
core files plus every game in `games.json`. When you change caching behaviour or
the `CORE` list, bump `VERSION` in `sw.js`. Every page needs the manifest link,
icon links and `shared/pwa.js` (copy them from an existing page, fixing the
relative paths).

## Adding a game

1. Create `site/games/<slug>/index.html` and `site/games/<slug>/game.json`.
2. Start from the head of `site/games/second-shot/index.html` (meta tags,
   theme link, manifest/icons and `shared/pwa.js` with `data-root="../../"`).
3. Run `uv run minigames build` (or just `uv run minigames`) and check it on the hub.
4. Add it to the games table in `README.md`.
5. Put game rules in a plain module (like `gallery-guess/logic.js`) and test them in
   `tests/js/<slug>.test.mjs`. Run `uv run minigames test` before pushing; CI runs it too.

## Multiplayer (`shared/mesh.js`)

One phone per player, no server: only static files plus public STUN servers (which
just tell a browser its public address; no game data passes through them).

- **Joining**: a member shows an invite QR/link (`#j=` + compact WebRTC offer). The
  newcomer answers with a reply QR/link (`#r=`). The inviter scans it with the phone
  camera: the reply opens in a new tab, which hands it to the game tab over
  `BroadcastChannel` (falls back to copy/paste). Or either side scans in the page
  (Scan buttons; needs https for the camera). Any member can invite.
- **Mesh**: after that one manual exchange, everyone connects to everyone, with
  signaling relayed over the existing connections. Broken links heal the same way.
- **Shared state**: `room.state` is owned by one leader and copied to all. Members send
  their own facts (`room.setFacts`), the leader merges them (`room.mergeFacts` hook).
  Game messages: `room.broadcast` / `room.send`; files: `room.sendBulk`.
- **Leader**: the online member with the lowest join number. If it disappears (~7 s
  without pings), the next one takes over with `term + 1`; leaving hands over first.
  Game timers must therefore live in a leader loop that can start at any moment
  (see the leader `setInterval` in Gallery Guess).
- Limits: about 12 players; some strict networks block direct connections (no TURN).
  Testing: several tabs of one browser work as separate players.

### Security (multiplayer)

Everything another phone sends is untrusted: state copies, facts, messages, files.

- Never put peer data into `innerHTML` unescaped, numbers included: use `esc()`, or
  `textContent`. Coerce types with `typeof`/`Number.isFinite`, never `String(x)` or
  `x | 0` on peer data (`{"toString": 1}` from JSON makes those throw).
- mesh.js validates ids (`isId`: they become object keys, so no `__proto__`), binds
  each message to the connection it came from (no spoofed senders when a direct link
  exists), only accepts state from the leader it names, cleans state with
  `cleanState()` and caps files at 8 MB. Games add `room.cleanGame` for their fields
  (see `logic.js`) and validate their own messages.
- Multiplayer pages set a Content-Security-Policy with `script-src 'self'` and keep
  all JS in files (no inline scripts or `on*=` handlers), so injected markup can't run.
  tests/test_site.py enforces this.
- Known limit: players are trusted not to cheat. A player can still claim the lead by
  sending a higher term, and could peek at photo owners with devtools.

## Games

### Second Shot (`site/games/second-shot/`)

Players take turns clicking twice, trying to hit a target interval (default 1 s,
configurable to the millisecond). Times are scored in whole milliseconds.

- Pages: setup → one timer page per turn → round results → … → winner.
- Each round the player(s) furthest from the target are out; if everyone ties,
  the round is replayed. Last player left wins.
- Hitting the target exactly (0 ms off) wins the game instantly.
- Timer can be shown or hidden while running (setup option).
- **GOAT**: the closest shot ever made at each target time, stored per browser in
  `localStorage["minigames:second-shot:goat"]` as `{ [targetMs]: { name, time, at } }`.
  Shown on setup, during turns, on results and on the winner page.
- Settings (players, target, timer visibility) persist in
  `localStorage["second-shot-settings"]`.

### Gallery Guess (`site/games/gallery-guess/`)

One phone per player over `shared/mesh.js`. Rules live in `logic.js` (tested).

- Lobby: join by QR, pick up to 5 photos (resized to 1280 px JPEG in the browser),
  tap Ready. Photos go straight to every other phone. The leader can start once at
  least 2 players are ready and every ready phone has every photo.
- Rounds (max 20): photo + everyone in the game as options. 10 s, timed on each phone
  from the moment the photo shows. Points: 100 − 8 per second, min 10; wrong = 0.
  You may guess your own photo. Late joiners can guess too.
- Reveal 5 s, then the next photo; at the end, standings and a gallery with owners.
  "Play again" returns to the lobby; photos stay picked, everyone taps Ready again.
- Seats: `sessionStorage`/`localStorage["minigames:gallery-guess:seats"]` let a refreshed or
  re-invited phone take its old seat (and score) back.
- Owner secrecy: a phone knows who sent each photo (that's how it can reveal the
  owner); the UI never shows it before the reveal, but devtools could.
