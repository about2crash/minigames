# AGENTS.md

Notes for AI coding agents (and humans) working in this repo.

## What this is

**Minigames**: a collection of party games for one shared screen (pass the phone
or laptop around). It is a **static site** in `site/`, deployed to **GitHub Pages**
by `.github/workflows/pages.yml` on every push to `main`. There is no backend.

Python + [uv](https://docs.astral.sh/uv/) is only tooling:

```sh
uv run minigames            # build games.json, serve site/ at http://127.0.0.1:8765/
uv run minigames build      # only regenerate site/games.json
uv run minigames --host 0.0.0.0   # test on a phone on the same network
```

## Layout

```
site/                      everything that gets deployed
  index.html               hub: reads games.json, shows one card per game
  games.json               GENERATED by `minigames build` (committed so the site works as-is)
  shared/theme.css         shared look: color tokens (light + dark), type, buttons, panels
  shared/pwa.js            registers the service worker (include in every page with data-root)
  manifest.webmanifest     PWA manifest; the hub is the installable app (start_url ./)
  sw.js                    service worker: network-first with offline cache, precaches games.json games
  icons/                   PWA icons, drawn by `uv run minigames icons`
  games/<slug>/
    game.json              { title, tagline, players, order } shown on the hub
    index.html             the whole game: markup, game CSS, game JS
src/minigames/cli.py       `build`, `serve` and `icons` commands (standard library only)
src/minigames/icons.py     stopwatch icon drawn with the standard library
.github/workflows/pages.yml  uv run minigames build -> upload site/ -> deploy Pages
```

## Rules

- **Static only.** No server APIs, no build step beyond `games.json`. Anything a
  game needs to remember goes in the browser's `localStorage` (wrap in try/catch).
- **Relative paths only.** Pages serves the site under `/<repo-name>/`, so never use
  leading `/` in hrefs, srcs or fetches. A game links the theme as
  `../../shared/theme.css` and back to the hub with `<a class="back" href="../../">`.
- **Shared style.** Use the tokens in `shared/theme.css` (`--bg`, `--panel`, `--fg`,
  `--muted`, `--line`, `--accent`, `--good`, `--face`, `--face-fg`, `--display`,
  `--body`, `--mono`). Don't hard-code colors; keep light and dark mode working.
  Fonts: Big Shoulders Display (headings), IBM Plex Sans (body), IBM Plex Mono (numbers).
- **Mobile first-class.** Touch targets at least 44px, `pointerdown` for timing-
  critical input, no hover-only features, layout must work at 360px wide, respect
  safe-area insets and `prefers-reduced-motion`.
- **Keyboard too.** Space/Enter should drive the main game action where it makes sense.
- No dependencies in `pyproject.toml` unless really needed; the site loads no JS libraries.

## PWA

The hub (`site/index.html`) is installable. `sw.js` is network-first, so online
users always get the latest files; offline it serves the cache. It precaches the
core files plus every game in `games.json`. When you change caching behaviour or
the `CORE` list, bump `VERSION` in `sw.js`. Every page needs the manifest link,
icon links and `shared/pwa.js` (copy them from an existing page, fixing the
relative paths).

## Adding a game

1. Create `site/games/<slug>/index.html` and `site/games/<slug>/game.json`.
2. Start from the head of `site/games/second-shot/index.html` (meta tags, fonts,
   theme link, manifest/icons and `shared/pwa.js` with `data-root="../../"`).
3. Run `uv run minigames build` (or just `uv run minigames`) and check it on the hub.
4. Add it to the games table in `README.md`.

## Games

### Second Shot (`site/games/second-shot/`)

Players take turns clicking twice, trying to hit a target interval (default 1 s,
configurable to the millisecond). Times are scored in whole milliseconds.

- Pages: setup → one timer page per turn → round results → … → winner.
- Each round the player(s) furthest from the target are out; if everyone ties,
  the round is replayed. Last player left wins.
- Hitting the target exactly (0 ms off) wins the game instantly.
- Timer can be shown or hidden while running (setup option).
- **GOAT**: the closest shot ever made at each target time, stored per browser in
  `localStorage["minigames:second-shot:goat"]` as `{ [targetMs]: { name, time, at } }`.
  Shown on setup, during turns, on results and on the winner page.
- Settings (players, target, timer visibility) persist in
  `localStorage["second-shot-settings"]`.
